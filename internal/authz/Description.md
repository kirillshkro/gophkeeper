# internal/authz

## Назначение

Пакет `authz` реализует авторизацию доступа к информации: проверяет, что
каждый авторизованный клиент получает доступ **только к своим данным**
(данным владельца). Это слой политики: кто и к чему может.

Пакет предполагает, что пользователь уже аутентифицирован (`auth`). Он
ответит "разрешить/запретить" на конкретное действие с конкретным ресурсом.

## Отвечает за

- проверку, что запрос относится к данным владельца;
- проверку типа доступа (чтение / изменение / удаление) — кто и что может;
- централизованное принятие решений о доступе (единая точка, не разброс
проверок по коду);
- отказ в доступе к чужим данным.

## Требования

### Функциональные

1. Проверка владения ресурсом:
   - перед каждым доступом к данным подтверждать, что `ownerID == userID`;
   - при несоответствии — `ErrUnauthorized`.
2. Проверка типа действия:
   - чтение (GET) — владелец;
   - изменение/удаление (PUT/DELETE) — владелец (при необходимости —
     дополнительные проверки, например подтверждение паролем).
3. Единый входной метод для решений (DRY): одна функция/интерфейс, через
   который проходят все проверки доступа.
4. Интеграция с `auth`: текущий пользователь берётся из валидного токена.
5. Логирование отказов в доступе (без раскрытия чужих данных).

### Неразметочные

- Возврат `(value, error)` / `bool`.
- Исчерпывающая godoc-документация.
- Покрытие тестами не менее 70% (включая все ветвления доступа).
- Решения не должны раскрывать структуру чужих данных (безопасность).
- Пакет должен быть чистым: легко мокнуть в тестах (через интерфейс).

## Ожидаемое API

- Тип `Action` (enum): `ActionRead`, `ActionWrite`, `ActionDelete`.
- `CanAccess(ownerID, userID string, action Action) error`.
- Middleware/хелпер: `RequireAuth(r *http.Request) (User, error)` —
  берёт пользователя из валидного токена (`auth`) и проверяет (`authz`).
- Ошибки: `ErrUnauthorized`, `ErrNotOwner`, `ErrInsufficientAccess`.

## Зависимости

- `gophkeeper/internal/auth` (идентификация пользователя из токена).
- Не зависит от `storage`, `data`, `sync` (политика выше уровня данных).
