# internal/user

## Назначение

Пакет `user` реализует управление пользователями сервера GophKeeper. Он отвечает
за учётные записи: создание при регистрации, хранение профиля и управление
данными пользователя. Это слой домена "кто этот пользователь".

Пакет не содержит аутентификации (за это отвечает `auth`) и авторизации
(за это отвечает `authz`) — он только предоставляет данные пользователя,
которые нужны этим пакетам.

## Отвечает за

- процедуру регистрации нового пользователя;
- хранение и управление профилем пользователя;
- предоставление данных пользователя для проверки credentials (пакет `auth`);
- обновление и удаление учётной записи.

## Требования

### Функциональные

1. Реализовать процедуру первичной регистрации пользователя:
   - принимать формат данных регистрации (логин, пароль, данные профиля —
     по спецификации);
   - проверять доступность логина (уникальность) и валидность полей;
   - при успехе создавать профиль пользователя.
2. Предоставить получение данных пользователя по логину/ID (для `auth` и
   `api`).
3. Гарантировать, что пароль хранится только в виде хэша (через `security`)
   и никогда не попадает в хранилище в открытом виде.
4. Поддерживать обновление (editing) и удаление учётной записи.
5. Состояние пользователя (активен/заблокирован/удалён) должно быть явно
   задано и учитываться при доступе.

### Неразметочные

- Возврат `(value, error)`; ошибки — `errors.New` / `errors.Join`, проверка
  типов — `errors.As` / `errors.Is`.
- Исчерпывающая godoc-документация на каждый экспортный элемент.
- Покрытие юнит-тестами не менее 70%.
- Логирование через `slog` (не `fmt`).
- Размер файла не более 250 строк кода; при росте — разбивать на связанные
  файлы.
- SOLID/DRY: пакет должен быть расширяемым без изменения существующего кода.

## Ожидаемое API

- Тип `User` — модель пользователя (логин, метаданные профиля, статус,
  хеш пароля, версия).
- Интерфейс или набор функций `UserService` (методы принимают не более
  двух параметров):
  - `Register(regData) (User, error)`;
  - `GetByLogin(login) (User, error)`;
  - `Update(id, user) error`;
  - `Delete(id) error`.
- Ошибки: `ErrUserNotFound`, `ErrLoginTaken`, `ErrUserInactive`,
  `ErrInvalidUser`.

## Зависимости

- `gophkeeper/internal/data` (типы данных).
- `gophkeeper/internal/security` (хэширование пароля).
- `gophkeeper/internal/storage` (персистентность).

Зависит только от "ниже" — не должен зависеть от `auth`, `authz`, `api`,
`sync`, `client` (избегание циклических и обратных зависимостей).
