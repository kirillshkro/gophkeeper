# internal/security

## Назначение

Пакет `security` реализует механизмы безопасности GophKeeper: защиту данных
при передаче и хранении. Это криптографический ядро системы.

Пакет предоставляет низкоуровневые криптографические примитивы, которые
используют `auth`, `storage`, `sync` и `client`.

## Отвечает за

- хэширование паролей пользователей;
- шифрование/дешифрование приватных данных;
- генерацию, подпись и проверку аутентификационных токенов;
- управление ключами шифрования;
- обеспечение безопасной передачи (TLS) на стороне сервера.

## Требования

### Функциональные

1. Хэширование паролей:
   - использовать современный, устойчивый к перебору алгоритм
     (argon2 / bcrypt / pbkdf2 — актуальный по документации);
   - никогда не хранить пароль в открытом виде;
   - проверить пароль через `VerifyPassword(plain, hash) error`.
2. Шифрование приватных данных:
   - шифровать содержимое (пароли, карты, бинарные данные) **перед** записью
     в хранилище;
   - расшифровывать при чтении **для владельца**;
   - использовать алгоритм с аутентифицированной шифрованием (AEGS,
     например, AES-GCM).
3. Управление ключами:
   - генерация мастер-ключа пользователя;
   - хранение ключа (зашифрованного/связанного с аккаунтом);
   - использование ключа для шифрования данных.
4. Подпись и проверка токенов:
   - подпись токена (HMAC/JWS) с использованием секретного ключа;
   - проверка подписи и срока действия.
5. Безопасная передача:
   - обеспечение TLS на стороне сервера (сертификат/ключ);
   - отключение небезопасных шифров/протоколов.

### Неразметочные

- Ключи, пароли и секреты **не должны попадать** в логи (`slog`), ответы и
  panic-сообщения.
- `(value, error)`.
- Алгоритмы должны быть актуальными — проверять через актуальную документацию
  (context7/fetch) перед внедрением.
- Исчерпывающая godoc-документация.
- Покрытие тестами не менее 70% (включая round-trip шифрования, edge-cases).
- Чистая криптография: не зависит от `data`, `user` (ввозимо в любой слой).

## Ожидаемое API

- `HashPassword(plain string) (string, error)`.
- `VerifyPassword(plain, hash string) error`.
- `Encrypt(plain, key []byte) ([]byte, error)`.
- `Decrypt(cipher, key []byte) ([]byte, error)`.
- `SignToken(payload []byte, key []byte) ([]byte, error)`.
- `VerifyToken(signature, payload []byte, key []byte) error`.
- `GenerateMasterKey() ([]byte, error)`.
- Ошибки: `ErrInvalidPasswordHash`, `ErrDecryptionFailed`, `ErrInvalidSignature`,
  `ErrKeyInvalid`.

## Зависимости

- Стандартная библиотека `crypto` (aes, hmac, sha256) + при необходимости
  `golang.org/x/crypto` (argon2/bcrypt/pbkdf2) — добавить в `go.mod` при
  реализации.
- Не зависит от других пакетов модуля.
