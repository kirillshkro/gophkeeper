# internal/storage

## Назначение

Пакет `storage` реализует хранение данных GophKeeper: абстракцию хранилища,
выбор хранилища и формат хранения данных. Он отвечает на вопросы "где" и
"в каком формате" лежат данные.

Пакет нужен и серверу (персистентность данных пользователей), и клиенту
(локальное хранилище).

## Отвечает за

- определение общего интерфейса хранилища;
- реализацию конкретных адаптеров хранилища (SQL, файл, память), в качестве основного хранилища выступает реплицируемая БД на основе СУБД PostgreSQL;
- механизм выбора хранилища/формата (сервер и клиент);
- персистентность и атомарность операций записи;
- работу с метаданными.

## Требования

### Функциональные

1. Определить стабильный интерфейс `Storage` для CRUD данных пользователя:
   - запись, чтение, обновление, удаление;
   - перечисление данных владельца.
2. Реализовать выбор хранилища: пользователь/сервер выбирает тип
   хранилища (например, SQL, JSON-файл, память) и формат хранения данных
   (JSON, бинарный) — по спецификации "выбор хранилища и формат хранения".
3. Поддерживать несколько форматов хранения (например, JSON и бинарный)
   — формат выбирается пользователем через конфиг.
4. Гарантировать атомарность операций записи и целостность данных (no partial
   writes).
5. Шифровать данные перед записью (через `security`).
6. Работать с метаданными (хранить/задавать произвольные текстовые ключи).

### Неразметочные

- Интерфейс `Storage` — стабильный; адаптеры — расширяемые (SOLID,
  Open/Closed Principle).
- `(value, error)`.
- Атомарность и транзакционность записи.
- Исчерпывающая godoc-документация.
- Покрытие тестами не менее 70%.
- Логирование через `slog`.
- Файлы не более 250 строк; при росте — разбивать на подпакеты/файлы.

## Ожидаемое API

- Интерфейс `Storage`:
  - `Save(item Item) error`;
  - `Get(id string) (Item, error)`;
  - `Update(id string, item Item) error`;
  - `Delete(id string) error`;
  - `List(ownerID string) ([]Item, error)`.
- Фабрика: `NewStorage(cfg *Config) (Storage, error)` — создаёт адаптер по
  выбранному типу/формату.
- Структура `Config` (тип хранилища, формат, параметры, путь).
- Ошибки: `ErrNotFound`, `ErrConflict`, `ErrStorageFull`, `ErrCorruptData`.

## Зависимости

- `gophkeeper/internal/data` (типы данных).
- `gophkeeper/internal/security` (шифрование при хранении).
- Конкретные адаптеры (SQL/SQLite, JSON-файл, память) — реализуются в подпакете
  `internal/storage/...` (создаются при реализации).

Не зависит от `api`, `sync`, `user`, `auth` (ниже уровня).
