# internal/data

## Назначение

Пакет `data` — модель данных GophKeeper. Он определяет типы хранимой
информации и их метаданные. Это базовый (leaf) слой без бизнес-логики: только
структуры данных и их валидация.

Все остальные пакеты (`storage`, `sync`, `api`, `client`, `protocol`)
опираются на модели из этого пакета, поэтому он должен быть стабильным.

## Отвечает за

- определение типов данных (по спецификации);
- хранение произвольной текстовой метаданных для любого типа;
- валидация полей;
- версионирование данных (поле `Version`) для синхронизации.

## Требования

### Функциональные

Поддерживать типы данных из спецификации:

1. **Пары логин/пароль** — поле логин, поле пароль (сам пароль хранится в
   хранилище уже зашифрованным/в виде хэша — логика в `security`/`storage`).
2. **Произвольный текст** — произвольное текстовое содержимое.
3. **Произвольные бинарные данные** — произвольный бинарный blob.
4. **Данные банковских карт** — номер карты, срок действия, CVV и т.д.
   (зашифрованы при хранении).

Для **любого** типа данных — возможность хранить произвольную текстовую
метаданную информацию:

- принадлежность данных к веб-сайту, личности или банку;
- списки одноразовых кодов активации (OTP);
- произвольные другие текстовые ключ-значение.

Дополнительно:

5. Базовая сущность `Item` с обязательными полями: `ID`, `OwnerID`, `Type`,
   `Metadata`, `Version`, `CreatedAt`/`UpdatedAt`.
6. Расширяемость: новый тип данных = новый тип + новый `Type`, без
   изменения существующих типов (Open/Closed).
7. Валидация полей при создании/обновлении (например, формат карты/логина).
8. Для обработки разных типов данных использовать `type switch`
   (не прямое приведение типа).

### Неразметочные

- `(value, error)`; конструкторы — не более двух параметров.
- Исчерпывающая godoc-документация на каждый экспортный тип/поле.
- Покрытие тестами не менее 70%.
- Модель должна быть независимой от персистентности и транспорта.

## Ожидаемое API

- `type ItemType string` — enum типов: `TypeCredential`, `TypeText`,
  `TypeBinary`, `TypeCard`.
- `type Metadata` — произвольные текстовые ключи (например,
  `map[string]string` или структура с известными ключами + произвольными).
- Структура/интерфейс `Item` (базовая модель).
- Конкретные типы: `Credential`, `Text`, `Binary`, `Card`.
- Функции конструкторов: `NewCredential(login, password) (Item, error)`,
  `NewText(content, meta) (Item, error)` и т.д.
- Методы: `Item.Type() ItemType`, `Item.OwnerID() string`,
  `Item.Metadata() Metadata`.
- Ошибки: `ErrInvalidField`, `ErrUnknownType`, `ErrEmptyData`.

## Зависимости

- Стандартная библиотека.
- Не зависит от других пакетов модуля (это leaf-слой).
