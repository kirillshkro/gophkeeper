# internal/protocol

## Назначение

Пакет `protocol` определяет протокол взаимодействия клиента и сервера
GophKeeper: контракт, endpoints, форматы payloads и механизмы аутентификации.

Это «контракт» системы: клиент и сервер должны использовать один и тот же
пакет для совместимости. Пакет находится на уровне выше реализации — он
не знает, как устроен сервер или клиент, только что между ними передаётся.

## Отвечает за

- описание всех endpoints (метод, путь, параметры);
- форматы запросов и ответов (payloads);
- механизм аутентификации (заголовок `Authorization`);
- версионирование протокола (совместимость клиент/сервер);
- валидацию payloads.

## Требования

### Функциональные

1. Описать все endpoints системы (по спецификации):
   - регистрация;
   - аутентификация;
   - CRUD данных;
   - синхронизация;
   - передача данных владельцу по запросу.
2. Описать форматы запросов/ответов (payloads):
   - регистрация (логин, пароль, профиль);
   - аутентификация (token);
   - CRUD данных (item, metadata, version);
   - синхронизация (изменения, версии, дельта).
3. Описать механизм аутентификации:
   - заголовок `Authorization: Bearer <token>`;
   - формат и срок действия токена.
4. Обеспечить версионирование протокола:
   - версия протокола в запросе/ответе;
   - совместимость новых/старых клиентов и сервера.
5. Валидация payloads:
   - проверка корректности полей перед обработкой;
   - ошибки валидации — с понятными сообщениями.
6. (Необязательно, по спецификации) Описать протокол в формате
   Swagger/OpenAPI.

### Неразметочные

- Контракт должен быть стабильным и полностью документированным.
- `(value, error)`.
- Исчерпывающая godoc-документация.
- Покрытие тестами не менее 70%.
- Пакет не должен зависеть от реализации (`api`, `client`) — это контракт
  выше уровня.

## Ожидаемое API

- `type ProtocolVersion string` (версия протокола).
- Структуры payloads: `RegisterRequest`, `LoginRequest`, `LoginResponse`,
  `DataRequest`, `DataResponse`, `SyncRequest`, `SyncResponse`, `Token`,
  `Change`.
- Enums/константы: типы данных, действия, HTTP-статусы.
- Функции валидации: `ValidateRegister(req) error`, `ValidateData(req) error`.
- Функции сериализации/десериализации (JSON): `Marshal`, `Unmarshal`.
- Ошибки: `ErrInvalidPayload`, `ErrUnsupportedVersion`, `ErrAuthRequired`.

## Зависимости

- `gophkeeper/internal/data` (типы данных для payloads).
- Стандартная библиотека `encoding/json`.
- Не зависит от `api`, `client`, `cmd` (контракт наверху).
