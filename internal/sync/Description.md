# internal/sync

## Назначение

Пакет `sync` реализует синхронизацию данных: согласование приватных данных
между сервером и несколькими авторизованными клиентами одного владельца.

Это ключевой сценарий спецификации: пользователь может синхронизировать данные
между несколькими устройствами/клиентами, и они должны быть согласованы.

## Отвечает за

- отправление локальных изменений клиента на сервер;
- получение изменений с сервера на клиент;
- версионирование данных (актуальность);
- разрешение конфликтов (когда два клиента изменили одно и то же);
- инкрементальную синхронизацию (только дельта, а не всё).

## Требования

### Функциональные

1. Механизм синхронизации:
   - клиент отправляет локальные изменения на сервер;
   - клиент получает изменения с сервера;
   - после синхронизации все клиенты владельца имеют одинаковые данные.
2. Версионирование:
   - каждое изменение имеет версию;
   - версия позволяет определить, актуальное или устаревшее изменение;
   - при конфликте версии — разрешается.
3. Разрешение конфликтов:
   - если два клиента изменили одно и то же поле — механизм разрешает
     конфликт (по спецификации — на усмотрение исполнителя: last-write-wins /
     merge / ручной выбор);
   - решение должно быть детерминированным и воспроизводимым.
4. Инкрементальная синхронизация:
   - отправка/приём только изменений (дельта) с версии X, а не всех данных;
   - отслеживание последней синхронизированной версии клиента.
5. Гарантии целостности:
   - после успешной синхронизации — все клиенты имеют согласованные данные;
   - при ошибке — данные не повреждены (откат/повтор).
6. Безопасность: синхронизация только для владельца (через `auth`/`authz`).

### Неразметочные

- Использование горутин/каналов для независимых потоков (отправка/приём),
  там где возможно (patтерн многопоточности).
- `(value, error)`.
- Исчерпывающая godoc-документация.
- Покрытие тестами не менее 70% (включая сценарии конфликтов).
- Логирование через `slog`.
- Синхронизация должна быть идемпотентной (повторный запуск — безопасен).

## Ожидаемое API

- `SyncUp(client *Client) error` — отправка локальных изменений на сервер.
- `SyncDown(client *Client) ([]Change, error)` — получение изменений с сервера.
- `ResolveConflict(a, b Item) Item` — разрешение конфликта между двумя
  версиями.
- Тип `Change` (item, action, version, timestamp).
- Поле `Version` в данных (через `data`).
- Ошибки: `ErrConflict`, `ErrSyncFailed`, `ErrStaleVersion`, `ErrNetwork`.

## Зависимости

- `gophkeeper/internal/data` (типы данных).
- `gophkeeper/internal/storage` (персистентность).
- `gophkeeper/internal/security` (шифрование при передаче/хранении).
- `gophkeeper/internal/authz` (проверка владельца).
