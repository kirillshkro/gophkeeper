# cmd/server — точка входа сервера

## Назначение

Пакет `main` (командный интерфейс, binary) — точка входа сервера GophKeeper.
Он собирает и запускает сервер: конфигурацию, хранилище, API.

Пакет не содержит бизнес-логики — он только собирает компоненты и управляет
жизненным циклом.

## Отвечает за

- загрузку конфигурации сервера;
- инициализацию хранилища (выбор/формат из конфига);
- создание API-сервера (`net/http`) с хендлерами из `api`;
- запуск HTTP-сервера на указанном порту;
- управление жизненным циклом (старт, graceful shutdown);
- обработку сигналов (SIGTERM, SIGINT).

## Требования

### Функциональные

1. Загрузить конфигурацию сервера (из файла/флагов).
2. Инициализировать хранилище (выбор/формат из конфига).
3. Создать API-сервер с хендлерами из `api`.
4. Запустить HTTP-сервер на указанном порту.
5. Обработать graceful shutdown:
   - при получении SIGTERM/SIGINT — ожидать завершения активных запросов;
   - остановить сервер;
   - записать статус в лог.
6. Логирование через `slog`.

### Неразметочные

- `(value, error)`.
- Исчерпывающая godoc-документация.
- Покрытие тестами не менее 70%.
- Не должно содержать бизнес-логики (SOLID, Separation of Concerns).
- Не более 250 строк кода.
- Вывод через `slog` (не `fmt`).
- Методы принимают не более двух параметров.

## Ожидаемое API

- Функция `main()`.
- `run(cfg *config.Config) error` — запуск сервера.
- `setupServer(...) *http.Server` — сборка сервера.
- Ошибки: `ErrConfigLoadFailed`, `ErrServerStartFailed`, `ErrShutdownFailed`.

## Зависимости

- `gophkeeper/internal/api`.
- `gophkeeper/internal/config`.
- `gophkeeper/internal/storage`.
- `gophkeeper/internal/user`, `auth`, `authz`, `sync` (через `api`).
- Стандартная библиотека `net/http`, `os/signal`, `slog`.
