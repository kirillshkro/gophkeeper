# tests-specs — корневой пакет `gophkeeper`

## Назначение

Корневой пакет модуля содержит только документацию и общие определения; бизнес-логика
находится в `internal/` и `cmd/`. Тесты пакета подтверждают стабильность корня модуля,
целостность документации и работоспособность системы в целом.

## Группы тестов

### 3.1. Стабильность корня пакета

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Пакет не содержит бизнес-логики и импортов вне stdlib | статическая проверка (`go build`/`go vet`) без ошибок |
| 2 | Наличие godoc-комментария у пакета | лент-проверка документации (golangci-lint) |
| 3 | `doc.go` — точка входа документации, структура пакета не меняется без причины | стабильность (review) |

### 3.2. Интеграционные smoke-тесты системы

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | `go test -v -race ./...` | все тесты всех пакетов зелёные |
| 2 | `go vet ./...` + `golangci-lint run ./...` | без ошибок и предупреждений |
| 3 | Кросс-сборка CLI (`cmd/client`) и сервера (`cmd/server`) для Windows, Linux, macOS | бинарники собираются и запускаются (команда `version`) |
| 4 | Покрытие тестами по модулю | не менее 70% (среднее по пакетам, согласно SPECIFICATION.md) |

## Критерии готовности

- [ ] smoke-тесты зелёные;
- [ ] покрытие каждого пакета ≥ 70%;
- [ ] лinters чистые;
- [ ] кросс-платформенные бинарники собираются и корректно выводят версию/дату сборки.
