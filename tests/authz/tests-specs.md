# tests-specs — `gophkeeper/internal/authz` (авторизация доступа)

## 1. Общие положения

- Инструменты: `go test -v -race -cover`, `go.uber.org/mock`, захват `slog.Handler`.
- Пакет должен быть «чистым» и легко мокаться: в тестах используется только интерфейсная часть.
- Имена: `TestAuthz_<Функция>_<Сценарий>`, например `TestAuthz_CanAccess_OwnerRead`.
- Ключевая инвариант: доступ всегда только к данным владельца; отказ — без раскрытия чужих данных.

## 2. Моки

| Зависимость | Заменитель |
|---|---|
| `auth` (`Validate` — идентификация из токена) | gomock (MockAuth) |

## 3. Группы тестов

### 3.1. Проверка владения — `CanAccess(ownerID, userID, action)`

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | owner == userID, `ActionRead` | `nil` (разрешено) |
| 2 | owner == userID, `ActionWrite` | `nil` |
| 3 | owner == userID, `ActionDelete` | `nil` |
| 4 | owner ≠ userID, любое действие | `ErrNotOwner` (`errors.Is`) |
| 5 | Пустой ownerID или userID | `ErrUnauthorized` |
| 6 | Внутренняя ошибка (нечитательность ownerID) | `ErrInsufficientAccess`/ошибка |

### 3.2. Enum `Action` (покрытие всех ветвей `type switch`)

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | `ActionRead`, `ActionWrite`, `ActionDelete` | все разрешены владельцу |
| 2 | Незнакомя/невалидный `Action` (внешний ввод) | отказ (`ErrUnauthorized`/валидация) |

### 3.3. Middleware/хелпер — `RequireAuth(r *http.Request)`

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Валидный токен + совпадает владелец ресурса | `(User, nil)`, пользователь в контексте |
| 2 | Заголовок `Authorization` отсутствует | 401 |
| 3 | Токен невалиден/истёк | 401 |
| 4 | Токен валиден, ресурс чужого владельца | 403 |
| 5 | Запрещённое действие (policy) | 403 |
| 6 | В контексте сохраняется только `User` из валидного токена | `errors.Is`/проверка контекста |

### 3.4. Безопасность и логирование

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Запрещённый доступ (403) | лог записи (сlog) — без раскрытия структуры/содержимого чужих данных |
| 2 | Множественные отказы подряд | нет утечки данных в логи/ответы |

### 3.5. Конкурентность

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Параллельные вызовы `CanAccess`/`RequireAuth` | без гонок (`go test -race`) |

## 5. Критерии готовности

- [ ] покрытие ≥ 70% (включая все ветвления решений доступа);
- [ ] каждая ошибка (`ErrUnauthorized`, `ErrNotOwner`, `ErrInsufficientAccess`) — через `errors.Is`;
- [ ] пакет чистый: зависимости только «вверх» (`auth`), легко мокнется;
- [ ] godoc-документация у всех экспортных элементов.
