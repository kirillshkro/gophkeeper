# tests-specs — `gophkeeper/internal/data` (модель данных)

## 1. Общие положения

- Инструменты: `go test -v -cover`; пакет чистый (leaf), не зависит от других пакетов модуля.
- Пакет — модель данных: тестируются конструкторы, валидация, метаданные, версии, типизация.
- Имена: `TestData_New<Type>_<Сценарий>`, `TestMetadata_...`.
- Все данные — фиктивные (тестовые), без реальных чувствительных значений.

## 2. Моки

| Зависимость | Заменитель |
|---|---|
| — | Пакет не имеет зависимостей; моки не нужны |
| Файловая система | не нужна (чистый пакет) |

## 3. Группы тестов

### 3.1. `ItemType` enum

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | `TypeCredential`, `TypeText`, `TypeBinary`, `TypeCard` | все валидны |
| 2 | Неизвестный тип (внешний ввод) | `ErrUnknownType` (`errors.Is`) |

### 3.2. Конструкторы

#### NewCredential(login, password)

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Валидный login + password | `(Credential, nil)` |
| 2 | Пустой login | `ErrEmptyData`/`ErrInvalidField` |
| 3 | Пустой пароль | `ErrEmptyData` |
| 4 | Неверный формат логина (если валидация) | `ErrInvalidField` |

#### NewText(content)

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Валидный текст (включая UTF-8, крупный) | `(Text, nil)` |
| 2 | Пустой текст | `ErrEmptyData` |

#### NewBinary(blob)

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Валидный blob | `(Binary, nil)` |
| 2 | Очень крупный payload (MB) | `(Binary, nil)`, без ошибок |
| 3 | Пустой blob | `ErrEmptyData` |

#### NewCard(number, exp, cvv, metadata)

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Валидная карта (номер, срок, CVV) | `(Card, nil)` |
| 2 | Неверный номер карты (Checksum/Luhn) | `ErrInvalidField` |
| 3 | Истёкший срок действия | `ErrInvalidField` |
| 4 | Неверный CVV (длиной < 3) | `ErrInvalidField` |
| 5 | Неверный формат даты (MM/YY) | `ErrInvalidField` |

### 3.3. Метаданные (Metadata)

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Пустые метаданные | ok (пустое map/структура) |
| 2 | Произвольные ключи (site, bank, person, OTP) | сохранены, читаются |
| 3 | Не-ASCII значения (UTF-8) | сохранены, читаются |
| 4 | Очень длинные значения | сохранены |
| 5 | Дубликаты ключей (при обновлении) | последующее значение — приоритет |

### 3.4. Базовая сущность `Item`

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | `Item.Type()` | возвращает `ItemType` |
| 2 | `Item.OwnerID()` | возвращает ownerID |
| 3 | `Item.Metadata()` | возвращает `Metadata` |
| 4 | `Version` — при создании | 1 (или 0 по дизайну) |
| 5 | `Version` — при обновлении | возрастает (старая < новая) |
| 6 | `CreatedAt`/`UpdatedAt` | установлены; `UpdatedAt` ≥ `CreatedAt` |
| 7 | Пустой `OwnerID` | ошибка/нулевое значение (зафиксировать) |

### 3.5. Валидация (покрытие всех ветвей `type switch`)

| # | Тип | Сценарий | Ожидаемо |
|---|---|---|---|
| 1 | `Credential` | валидация полей | `nil`/ошибка |
| 2 | `Text` | валидация полей | `nil`/ошибка |
| 3 | `Binary` | валидация полей | `nil`/ошибка |
| 4 | `Card` | валидация полей | `nil`/ошибка |
| 5 | Неизвестный тип | fallback | `ErrUnknownType` |

### 3.6. Сериализация (JSON round-trip, если реализовано)

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Marshal → Unmarshal каждый тип | идентичное содержимое |
| 2 | Невалидный JSON | ошибка |
| 3 | Порядок полей / версия | стабильно |

## 4. Дополнительные сценарии

- **Типизация:** обработка разных типов данных через `type switch` — все ветвы покрыты.
- **Расширяемость:** новый тип данных = новый тип + новый `ItemType`, без изменения существующих (Open/Closed) — тестируется добавлением нового типа в тесте.
- **Независимость:** пакет не зависит от персистентности и транспорта (проверка импортов).

## 5. Критерии готовности

- [ ] покрытие ≥ 70%;
- [ ] все конструкторы + все ветвы `type switch` покрыты;
- [ ] все ошибки (`ErrInvalidField`, `ErrUnknownType`, `ErrEmptyData`) — через `errors.Is`;
- [ ] godoc-документация у всех экспортных типов/полей;
- [ ] пакет независим (не зависит от `storage`, `security`, `auth`, `api`).
