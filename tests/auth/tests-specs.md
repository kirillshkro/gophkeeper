# tests-specs — `gophkeeper/internal/auth` (аутентификация)

## 1. Общие положения

- Инструменты: `go test -v -race -cover`, `go.uber.org/mock`, захват `slog.Handler` для проверки логов.
- Группа тестов на функцию/метод; сценарии — `t.Run`; имена: `TestAuth_<Метод>_<Сценарий>`.
- Время (TTL токена, rate-limit) — инжестируемый clock (интерфейс `TimeProvider`/`*time.T`), чтобы тесты не зависели от реального времени.

## 2. Моки

| Зависимость | Заменитель |
|---|---|
| `user.UserService` (`GetByLogin`, `GetByID`) | gomock (MockUserService) |
| `security` (`VerifyPassword`, `SignToken`/`VerifyToken`, `Revoke`) | gomock / реальные примитивы |

## 3. Группы тестов

### 3.1. `Verify(login, password)` — проверка credentials

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Логин и пароль валидны | `nil` |
| 2 | Неверный пароль | `ErrInvalidCredentials` (`errors.Is`) |
| 3 | Пользователь не найден | `ErrUserNotFound` (`errors.Is`) |
| 4 | Пользователь заблокирован | `ErrUserInactive`/недопуск |
| 5 | Ошибка хранилища в `user` | пробрасывается через `errors.As` без потери контекста |

### 3.2. Выпуск токена — `IssueToken(ownerID)`

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Валидный ownerID | токен: payload с ownerID, подпись, TTL > 0 |
| 2 | Пустой/невалидный ownerID | ошибка |
| 3 | Контент токена | **нет** чувствительных полей (пароль/хеш/карты) |

### 3.3. Валидация токена — `Validate(token)` из `Authorization: Bearer`

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Валидный токен | `(User, nil)`, ownerID совпадает |
| 2 | Заголовок отсутствует | `ErrAuthRequired` |
| 3 | Токен истёк | `ErrTokenExpired` |
| 4 | Подпись невалидна | `ErrTokenInvalid` |
| 5 | Токен отозван (`Revoke`) | `ErrTokenInvalid` |
| 6 | Некорректный формат заголовка | `ErrAuthRequired` (без раскрытия) |
| 7 | Повторный `Validate` того же токена | детерминированный результат (идемпотентность) |

### 3.4. Отзыв токена — `Revoke(tokenID)`

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Валидный tokenID | после отзыва `Validate` → ошибка |
| 2 | Незнакомый tokenID | ошибка (`ErrTokenInvalid`/`ErrTokenNotFound`) |
| 3 | Отзыв при смене пароля/logout | все токены владельца невалидны |

### 3.5. Защита от перебора паролей

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | ≤ лимита неудачных попыток | `ErrInvalidCredentials` |
| 2 | > лимита | `ErrTooManyAttempts`; `Verify` отклоняет до сброса |
| 3 | Успешный вход сбрасывает счётчик | следующий вход — ок |
| 4 | Сброс при смене пароля | счётчик очищен |
| 5 | Сброс по времени (TTL rate-limit) | после ожидания — попытки разрешены |

### 3.6. Безопасность

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | `slog`-логи | в записях нет паролей/токенов/ключей |
| 2 | Payload токена | декодирование — только ownerID + метаданные, без секретов |
| 3 | Паники | не возникает при мусорном вводе (nil/пустые/битые данные) |

## 4. Дополнительные сценарии

- **Конкурентность:** параллельные `Validate` — без гонок (`go test -race`); состояние (отзывы, лимиты) под mutex.
- **Тайминги:** токен невалиден до момента выпуска (сдвиг clock вперёд) и валиден до expiry.

## 5. Критерии готовности

- [ ] покрытие ≥ 70%;
- [ ] каждая ошибка пакета (`ErrInvalidCredentials`, `ErrTokenExpired`, `ErrTokenInvalid`, `ErrTooManyAttempts`, `ErrUserNotFound`) проверяется через `errors.Is`;
- [ ] godoc-документация у всех экспортированных элементов;
- [ ] вывод только через `slog`, без `fmt`.
