# tests-specs — `gophkeeper/internal/user` (управление пользователями)

## 1. Общие положения

- Инструменты: `go test -v -cover`, `go.uber.org/mock`, захват `slog.Handler`.
- Пакет не содержит аутентификации/авторизации — только данные пользователя для `auth`/`authz`.
- Имена: `TestUser_Register_...`, `TestUser_GetByLogin_...`.
- Ключевые ошибки: `ErrUserNotFound`, `ErrLoginTaken`, `ErrUserInactive`, `ErrInvalidUser`.

## 2. Моки

| Зависимость | Заменитель |
|---|---|
| `storage` (персистентность) | gomock (MockStorage) / in-memory SQLite (GORM Gen) |
| `security` (`HashPassword`) | gomock / реальные |
| `data` | реальные (чистый пакет) |

## 3. Группы тестов

### 3.1. Регистрация — `Register(regData)`

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Валидная регистрация (логин, пароль, профиль) | `(User, nil)`; пароль хранится как **хэш** (assert по mock storage) |
| 2 | Логин уже занят | `ErrLoginTaken` (`errors.Is`) |
| 3 | Нет логина/пароля | `ErrInvalidUser` |
| 4 | Статус нового пользователя | `Active` (по дизайну) |
| 5 | Ошибка хранилища | внутренняя ошибка (проброшена через `errors.As`) |
| 6 | **Пароль в открытом виде в хранилище** | отсутствует (assert по mock storage) |

### 3.2. Получение данных — `GetByLogin(login)`, `GetByID(id)`

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Пользователь существует | `(User, nil)` |
| 2 | Пользователь не существует | `ErrUserNotFound` |
| 3 | Пароль в profile | хэш (не plain) |
| 4 | Профильные поля (email, metadata) | сохранены и читаются |

### 3.3. Обновление — `Update(id, user) error`

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Валидное обновление | `nil`, version+1 |
| 2 | Смена пароля | новый хэш; старый пароль не валиден |
| 3 | Не существует | `ErrUserNotFound` |
| 4 | Неправильный id | `ErrUserNotFound` |

### 3.4. Удаление — `Delete(id) error`

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Существующий пользователь | `nil`; `GetByLogin` → `ErrUserNotFound` (или `ErrUserInactive` при soft-delete) |
| 2 | Не существует | `ErrUserNotFound` |
| 3 | Данные удалённого пользователя | недоступны (через `authz` → `ErrNotOwner`/`ErrUserInactive`) |
| 4 | **Пароль удалённого пользователя** | хэш удалён/недоступен (assert по storage) |

### 3.5. Статус пользователя

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Блокированный пользователь | `ErrUserInactive` при доступе (auth) |
| 2 | Разблокировка | статус `Active`, доступ возможен |
| 3 | Удалённый пользователь | статус `Deleted`, доступ запрещён |

### 3.6. Безопасность

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Пароль в открытом виде в хранилище | отсутствует (assert по mock storage) |
| 2 | `slog`-логи | без паролей/хэшей |
| 3 | Паники | не возникают при битых данных/nil |

## 4. Дополнительные сценарии

- **Идемпотентность:** повторная `Register` с тем же логином — `ErrLoginTaken` (без изменения существующего).
- **Версионирование:** `version` пользователя возрастает при каждом обновлении.
- **Зависимости:** пакет зависит только от `data`, `security`, `storage` (ниже) — проверено по импортам.

## 5. Критерии готовности

- [ ] покрытие ≥ 70%;
- [ ] все ошибки (`ErrUserNotFound`, `ErrLoginTaken`, `ErrUserInactive`, `ErrInvalidUser`) — через `errors.Is`;
- [ ] пароль никогда не в открытом виде (хотя бы 3 ассерта);
- [ ] godoc-документация;
- [ ] пакет независим от `auth`, `authz`, `api`, `sync`, `client`.
