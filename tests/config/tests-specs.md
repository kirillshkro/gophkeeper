# tests-specs — `gophkeeper/internal/config` (конфигурация)

## 1. Общие положения

- Инструменты: `go test -v -cover`; файловые тесты — только через `t.TempDir()`.
- Пакет чистый (leaf) — не зависит от `api`/`sync`/`client`/`cli`/`user`; тестируется без мока.
- Имена: `TestConfig_Load<Тип>_<Сценарий>`, `TestConfig_Validate<Тип>_<Сценарий>`.
- Приоритет: флаги > переменные окружения > файл.

## 2. Моки

| Зависимость | Заменитель |
|---|---|
| Файловая система | `t.TempDir()` (временные TOML/JSON/INI файлы) |
| Переменные окружения | `t.Setenv` / `t.Setenv` (Go 1.17+) |
| `storage` (валидация типов) | реальные |

## 3. Группы тестов

### 3.1. Загрузка конфигурации сервера — `LoadServerConfig(path string) (ServerConfig, error)`

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Валидный файл (TOML/JSON/INI) | `(ServerConfig, nil)`, все поля заполнены |
| 2 | Файл отсутствует | `ErrConfigMissing` |
| 3 | Битый/невалидный файл | `ErrConfigInvalid` |
| 4 | Неизвестный тип хранилища | `ErrUnknownStorageType` |
| 5 | Неверное значение (порт > 65535) | `ErrConfigInvalid` |
| 6 | Файл с пустыми полями | дефолтные значения применены |

### 3.2. Загрузка конфигурации клиента — `LoadClientConfig(path string) (ClientConfig, error)`

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Валидный файл | `(ClientConfig, nil)` |
| 2 | Файл отсутствует | `ErrConfigMissing` |
| 3 | Битый файл | `ErrConfigInvalid` |
| 4 | Неверный адрес сервера | `ErrConfigInvalid` |
| 5 | Неизвестный тип локального хранилища | `ErrUnknownStorageType` |

### 3.3. Валидация — `ValidateServer` / `ValidateClient`

| # | Сценарий (ServerConfig) | Ожидаемо |
|---|---|---|
| 1 | Порт 0–65535, валидное хранилище, TLS ok | `nil` |
| 2 | Порт вне диапазона / 0 | ошибка (если 0 — автопорт, зафиксировать) |
| 3 | Неизвестный тип хранилища | `ErrUnknownStorageType` |
| 4 | TLS: minVersion < TLS1.2 / запрещённые шифры | ошибка |
| 5 | TTL токена ≤ 0 | ошибка |
| 6 | Лимиты (размер данных, запросы/сек) ≤ 0 | ошибка |

| # | Сценарий (ClientConfig) | Ожидаемо |
|---|---|---|
| 1 | Валидный адрес сервера, валидное хранилище | `nil` |
| 2 | Неверный URL (не http/https) | ошибка |
| 3 | Интервал синхронизации ≤ 0 | ошибка |
| 4 | Таймаут ≤ 0 | ошибка |

### 3.4. Приоритет источников (флаги > env > file)

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Значение в трёх источниках | флаги выигрывают |
| 2 | Значение в env и file (без флагов) | env выигрывает |
| 3 | Значение только в file | file |
| 4 | Переменная окружения перекрывает файл | env выигрывает |

### 3.5. Секреты и расширяемость

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Дамп конфигурации (лог/ответ) | **нет** токенов/паролей (Redact) |
| 2 | Конфиг с неизвестными полями (новая версия) | загрузился, ошибки нет (Open/Closed) |
| 3 | Старый конфиг (мало полей) | загрузился, дефолты применены |

## 4. Дополнительные сценарии

- **Кросс-форматы:** если поддерживаются несколько форматов (TOML, YAML, JSON) — тесты на каждый формат.
- **Стандартные дефолты:** `LoadServerConfig` без явных значений — дефолты корректны (порт 8080/127.0.0.1 и т.д.).

## 5. Критерии готовности

- [ ] покрытие ≥ 70%;
- [ ] все ошибки (`ErrConfigMissing`, `ErrConfigInvalid`, `ErrUnknownStorageType`) — через `errors.Is`;
- [ ] файловые тесты только через `t.TempDir()`;
- [ ] логирование через `slog`, без `fmt`;
- [ ] пакет независим (не зависит от `api`, `sync`, `client`, `cli`, `user`).
