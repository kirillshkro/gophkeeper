# tests-specs — `gophkeeper/internal/cli` (CLI-команды клиента)

## 1. Общие положения

- Инструменты: `go test -v -race -cover`, `go.uber.org/mock`, захват stdout/stderr (`testing/io.Writer`).
- Пакет не содержит бизнес-логики — тестируется только диспетчеризация, парсинг, вывод.
- Имена: `TestCLI_<Команда>_<Сценарий>`, например `TestCLI_CmdRegister_LoginTaken`.
- Критерий кода выхода: `0` — успех, `≠0` — ошибка (по SPECIFICATION.md и Description.md).

## 2. Моки

| Зависимость | Заменитель |
|---|---|
| `client.Client` (ядро) | gomock (MockClient) |
| `config.ClientConfig` | реальные значения / файлы (`t.TempDir()`) |
| `version` | реальные (стабильные) значения |
| Вывод (`io.Writer`) | захват `bytes.Buffer` / `testing` |

## 3. Группы тестов

### 3.1. Диспетчеризация — `Run(cfg, opts) error`

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Подкоманда `register` | диспетчеризация в `CmdRegister`, exit 0 |
| 2 | Подкоманда `login`/`auth` | диспетчеризация в `CmdLogin` |
| 3 | Подкоманды `add`/`get`/`edit`/`delete` | диспетчеризация в соответствующие `Cmd*` |
| 4 | Подкоманда `sync` | диспетчеризация в `CmdSync` |
| 5 | Подкоманда `version` | вывод версии и даты сборки, exit 0 |
| 6 | Неизвестная подкоманда | usage-error, exit ≠ 0 |
| 7 | Подкоманда не передана | usage (help), exit ≠ 0/0 по дизайну (фиксировать в тесте) |

### 3.2. Парсинг флагов — `parseFlags` / `Options`

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Валидные флаги (`-server`, `--help`, `-v`) | корректные `Options` |
| 2 | Неизвестный флаг | ошибка usage, exit ≠ 0 |
| 3 | Отсутствие обязательного позиционного аргумента | `ErrNoArgs` |
| 4 | Флаг `--help`/`-h` | вывод справки, exit 0 |
| 5 | Пустые/двойные флаги | корректная обработка или ошибка |

### 3.3. `CmdRegister`

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | `client.Register` — успех | exit 0, понятное сообщение об успехе |
| 2 | Логин занят | exit ≠ 0, понятное сообщенье |
| 3 | Ошибка сети/сервера | exit ≠ 0 |

### 3.4. `CmdLogin`

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | `client.Login` — успех | токен сохранён, exit 0 |
| 2 | `ErrAuthFailed` | exit ≠ 0 |
| 3 | Истёк токен → авто-перелогин (если реализовано) | повторный вход, exit 0 |

### 3.5. Управление данными — `CmdAdd` / `CmdGet` / `CmdEdit` / `CmdDelete`

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Успешное действие (mock `client`) | exit 0, форматованный вывод |
| 2 | Отсутствует/некорректный id | ошибка, exit ≠ 0 |
| 3 | `CmdGet` — объект найден | вывод таблицы/списка (tabwriter) |
| 4 | `CmdGet` — объект не найден (`ErrNotFound`) | exit ≠ 0 |
| 5 | `CmdAdd`/`CmdEdit` — конфликт версий | exit ≠ 0, понятное сообщенье |
| 6 | **Секреты в выводе** | `password`, CVV, токен **не** попадают в stdout/stderr |
| 7 | Формат вывода | таблица/список с колонками (id, type, metadata, date) |

### 3.6. `CmdSync`

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Успешная синхронизация | exit 0, изменения применены |
| 2 | Конфликт (`sync.ErrConflict`) | exit ≠ 0, понятное сообщенье |
| 3 | Ошибка сети | exit ≠ 0 |
| 4 | Повторный запуск | идемпотентно |

### 3.7. `CmdVersion`

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Вывод | содержит версию и дату сборки (совпадает с пакетом `version`), exit 0 |

### 3.8. Коды выхода и логирование

| # | Сценарий | Ожидаемо |
|---|---|---|
| 1 | Успешное выполнение | exit 0 |
| 2 | Ошибка usage | exit 1 (или 2 по дизайну — зафиксировать в константах) |
| 3 | Бизнес-ошибка | exit 1, сообщение в stderr |
| 4 | Логирование | `slog`, без `fmt`; без секретов |

## 4. Дополнительные сценарии

- **Кроссплатформенность:** CLI собирается и работает на Windows, Linux, macOS (интеграционный smoke-тест: кросс-компиляция + запуск `version`).
- **Независимость от сети:** все тесты — офлайн, mock `client`.

## 5. Критерии готовности

- [ ] покрытие ≥ 70%;
- [ ] все субкоманды покрыты (register, login, add/get/edit/delete, sync, version);
- [ ] коды выхода соответствуют спецификации (0 / ≠0);
- [ ] секреты не в выводе (ассерт по захваченному stdout/stderr);
- [ ] логирование через `slog`.
